# 기술 설계 초안

## 확정 제약

형태는 내부 3D 데이터로 관리한다. 표현 단순화 방식은 미정이다. 튜토리얼 평가는 공정 단위이며 완제품 종합 점수를 도입하지 않는다.

## 제안: 모듈 경계

| 역할 | 책임 |
|---|---|
| 작업 관리 | 작업 ID 발급, 공정 배정, 시작·완료·중단 상태 |
| 공정 로직 | 입력 재료와 플레이어 입력에서 결과 생성 |
| 형태 모델 | 3D 형상 저장·변형·목표 비교 |
| 평가 | 해당 공정 관측값에서 공정 점수 생성 |
| 급여 원장 | 완료된 작업 ID로 한 번만 정산 |
| 수습 기록 | 작업별 평가 저장, 공정별 집계 |
| 튜토리얼 | 교육·해금·의뢰 마무리·입단 상태 |
| 표시 계층 | 안내, 작업 화면, 피드백과 기록부 |

엔진에 맞춰 클래스명과 실제 구조는 조정한다. 온라인 서버나 특정 프레임워크는 전제하지 않는다.

## 제안: 최소 저장 데이터

`schemaVersion`, `tutorialState`, `unlockedProcesses`, `jobs`, `evaluationRecords`, `paymentLedger`, `currencyBalance`, `workpieces`를 후보로 둔다. 작업 기록에는 작업 ID·공정·상태·결과 참조를 둔다. 급여 원장의 작업 ID는 중복될 수 없다. 점수 산식 버전도 남기면 변경 전 기록을 재해석하는 문제를 줄일 수 있다.

작업 완료, 평가 기록, 급여 정산, 잔액 갱신을 하나의 일관된 저장 처리로 묶는 것을 제안한다. 처리 도중 종료돼도 재실행에서 두 번 지급하지 않도록 한다. 구체 저장 형식과 복구 방식은 엔진 결정 후 선택한다.

## 제안: 3D 형태 후보 비교

| 후보 | 장점 | 한계 |
|---|---|---|
| 길이 방향 단면 연결 | 시제품이 비교적 단순하고 두께·깊이 보유 가능 | 복잡한 접힘과 임의 형상에 제약 |
| 변형 메시 | 표면 표현에 직접 사용 가능 | 변형 품질·자기 교차 처리 필요 |
| 복셀 | 국소 체적 변형 표현이 자연스러움 | 해상도별 메모리·표면 생성 비용 |

첫 실험 후보는 단면 모델이며 확정 선택이 아니다. 목표 형태 몇 개에 타격을 적용해 표현 한계와 피드백 가독성을 비교한 뒤 결정한다. 화면이 단순해도 원본 모델에서 깊이 정보가 유지되어야 한다.

## 미정

엔진, 언어, 대상 장치, 저장 포맷, 좌표·단위, 형상 정밀도, 성능 기준, 에셋 도구, 버전 관리 환경, 배포 형식. 현재 폴더에는 게임 실행 코드가 포함되어 있지 않다.
